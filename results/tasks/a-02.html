Done! Here's what changed and why it's so much faster:

### The problem: O(n²) double loop
The original code iterated over every `(i, j)` pair — that's `n × n` iterations, most of which just get thrown away by the `if i < j` guard. For 10,000 contacts that's **100 million comparisons**. It also re-normalized each name on every inner-loop iteration, so the same `.strip().lower()` was computed n times per record.

### The fix: O(n) grouping pass
```python
# 1. One pass: bucket each row index under its normalised name
groups = defaultdict(list)
for i, record in enumerate(records):
    key = record["name"].strip().lower()
    groups[key].append(i)

# 2. Emit pairs only within groups that have >1 member
for indices in groups.values():
    if len(indices) > 1:
        pairs.extend(combinations(indices, 2))
```

- **Single pass** over the records — each name is normalized exactly once.
- **Only actual duplicate groups** ever produce pairs; the vast majority of records (unique names) cost nothing beyond the initial bucketing.
- Complexity drops from **O(n²)** to **O(n + d)** where `d` is the number of duplicate pairs found — which is typically tiny compared to `n`.
