Clean a messy, multi-format CSV into a validated pipeline

Build a pipeline that cleans a messy, multi-format CSV (accounting negatives, four date formats, duplicates) into validated output with a monthly rollup.

solved by 3 of 3 models

The goal

Exactly what the agent was given — no answer key, no hints.

Prompt
`fixtures/raw_sales.csv` is a messy sales export. Turn it into a clean dataset and a short
summary report.

Apply exactly these cleaning rules:

1. **Trim** leading/trailing whitespace from every field.
2. **Amount:** strip the `$` and any thousands commas, and store it as a number with 2 decimal
   places (e.g. `"$1,234.56"` → `1234.56`). Amounts can be **negative** (refunds/adjustments),
   written either with a leading minus (`-$25.00` → `-25.00`) or in accounting style with
   parentheses (`($50.00)` → `-50.00`).
3. **Category:** lowercase it.
4. **Date:** convert to ISO `YYYY-MM-DD`. Inputs appear in four forms: `MM/DD/YYYY`,
   `YYYY-MM-DD`, `Month D, YYYY` (e.g. `March 7, 2026`), and `D-Mon-YYYY` (e.g. `7-Mar-2026`).
5. **Drop** any row missing a `date`, `amount`, or `category`.
6. **De-duplicate:** after cleaning, if two rows are identical in all three of `date`,
   `category`, and `amount`, keep only one.

Write two files in the current directory:

- `clean_sales.csv` with columns `date,category,amount`, sorted by `date` ascending (then by
  `category` ascending).
- `report.json`:
  ```json
  {
    "row_count": <int>,
    "total_amount": <number>,
    "by_category": {"<category>": <number>, ...},
    "by_month": {"<YYYY-MM>": <number>, ...}
  }
  ```
  where `total_amount`, each `by_category`, and each `by_month` value are sums of the cleaned
  amounts. The report must be consistent with `clean_sales.csv`.

What a correct run looks like

10 clean rows from 15 raw (3 missing + 2 duplicates dropped), four date formats normalized and accounting-negative amounts parsed; total = 5516.05, reconciled by category and by month.

How it's scored. Programmatic on the deliverable — the grader boots or runs the artifact and checks it behaves to spec (e.g. CRUD works and data persists across a restart).
